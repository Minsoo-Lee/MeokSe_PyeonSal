SSH 로컬 포트 포워딩

루프백 뚫기

홈서버의 MySQL은 127.0.0.1(자기 자신)에서 온 접속만 받아줘요. 그런데 맥에서 load.py를 돌리면 어떻게 그 문을 통과할 수 있을까요? 비밀은 — 진짜로 문을 통과하는 게 아니라, SSH가 문 안쪽까지 대신 들어가서 노크해준다는 거예요.

핵심은 “localhost”가 그림에 두 번 나온다는 것이에요. 맥의 localhost:3307과 홈서버의 localhost:3307은 이름만 같을 뿐, 물리적으로 완전히 다른 소켓이에요.

맥의 것은 SSH 클라이언트가 만들어둔 가짜 입구고, 홈서버의 것은 sshd가 마지막에 접속하는 진짜 loopback이에요. -L 3307:localhost:3307에서 앞의 3307은 맥 기준, 뒤의 localhost:3307은 — SSH로 로그인한 홈서버 기준이라는 게 이 트릭의 전부예요.

패킷 하나가 지나가는 다섯 걸음

  1. 맥

    ssh -fNL 3307:localhost:3307 user@homeserver 실행 → 맥의 localhost:3307에 SSH가 리스닝 포트를 하나 열어둠 (아직 아무 통신도 없음, 대기만).

  2. 맥

    load.py가 prep/.env의 DB_HOST=localhost, DB_PORT=3307대로 이 가짜 문에 접속.

  3. 맥 → 홈서버

    SSH 클라이언트가 이 데이터를 통째로 암호화해서, 이미 열려있는 SSH 연결(홈서버의 22번 포트)에 실어서 전송.

  4. 홈서버

    sshd가 데이터를 복호화하고, -L에 적힌 목적지 localhost:3307 — 즉 홈서버 자기 자신의 127.0.0.1:3307로 새 연결을 만들어 대신 접속.

  5. 홈서버

    MySQL이 소켓을 보니 발신지가 127.0.0.1 — 규칙대로 loopback이니 접속을 허용. 응답은 같은 경로를 거꾸로 타고 load.py에게 돌아감.

명령어 한 줄 해부

ssh -fNL 3307:localhost:3307 user@homeserver

-f -N -L
백그라운드 실행(f) + 셸은 안 띄우고 포워딩만(N) + 로컬 포트 포워딩(L). 셋 다 인자가 없어서 붙여 써도 동일.
앞의 3307
맥에 새로 여는 포트 번호. 이 숫자만 맥 기준.
localhost:3307
SSH로 로그인한 홈서버가 최종적으로 접속할 주소. 홈서버 입장의 “자기 자신”.
user@homeserver
이 터널을 열 수 있는 자격 — SSH 로그인 인증을 통과한 사람만 애초에 이 통로를 만들 수 있음.
